# 真实讲解质量验收

本轮使用现有块改进普通讲解的组织：直觉引入 → 先预测 → 动手观察 → 解释现象 → 变式自测。预测采用文字提示，正式练习仍沿用现有判题与复习卡流程；针对性补练继续以薄弱题型为主。未扩展计算能力，也未增加新的块类型。

## 固定案例与核对方法

案例定义在 `test/teaching-cases.mjs`：正弦波频率、阶乘递归、快速排序、英语名词复数、原始编码器—解码器架构、残差连接，以及带有明确操作约定的栈/队列讲义片段。

自动检查包含：

- 生产生成管线原有的文档结构、变量引用、图表数据和教学完整性校验，失败时走现有有界修复。
- 后续增加保存前独立模型复核与受限算例参考，结构和内容共用一次修复；行为、额外成本与真实漏检见[内容复核记录](content-review-2026-10-27.md)。之前的历史验收报告保留当时的流程，不倒推为已经经过新检查。
- 验收脚本记录生成耗时、首段正文、真实请求次数、网络重试和修复阶段，并定位四段顺序、预测是否包含计分块、观察段是否有活动块、末尾是否有变式题。

四段定位只是结构线索。标题齐全不代表教学内容正确；“PASS”只表示当前管线返回了成品，也不能把新增模型复核等同于事实认证。图文含义、题目答案、操作任务是否成立、预测是否被提前揭晓、变式是否真正改变推理条件，需要另行人工核对。每个案例都带有核对清单。

## 运行真实模型验收

在应用目录执行：

```shell
node --experimental-strip-types test/run-teaching-eval.mjs --help
node --experimental-strip-types test/run-teaching-eval.mjs --live --run=my-run --effort=low
```

脚本只有显式传入 `--live` 才调用模型。配置由进程读取本地环境文件，不输出或保存密钥、端点、模型配置和思考正文。它直接调用生产生成管线，不启动应用、不联网检索、不读写学习数据库。案例中的讲义是独立编写的验收材料。

本轮脚本使用 Node 24 的源码加载钩子；应用的运行环境要求仍以 README 为准。

串行运行，当前批量验收脚本给每个案例的整条管线最多 180 秒，保留生产管线的重试与修复行为；这层验收总预算独立于下文产品各阶段时限，可能提前结束 high/max 案例，不能据此断定是产品阶段超时。连续两题失败就停止，未执行案例不能计入成功率。可用 `--case=wave,recursion` 缩小范围。原始文档、提示词快照和清单存于 Git 忽略的 `data/teaching-eval/本轮名称/`。

`--resume` 只跳过已记录案例，不自动重做失败题，并要求提示词指纹和 effort 相同。新一轮复测请换名称。对照旧提示词时可以指定已存在的提交 SHA，例如：

```shell
node --experimental-strip-types test/run-teaching-eval.mjs --live --run=baseline-low --effort=low --prompt-revision=e5a7d8f
```

这个选项只从 Git 提取提示词到验收目录，不切换当前工作区。公平对照应固定案例输入、模型配置和 effort；单次运行只能说明这批样本，不能据此宣称总体成功率、固定提速幅度或学习效果提升。

## 无付费调用的桌面回归

停止开发服务后执行：

```shell
pnpm build
python test/run-learning-loop.py --teaching-only
```

该回归使用本地模型替身，验证提示词示例符合实际文档与公式契约、四段在桌面按顺序显示、滑块实际改变波形、预测与观察不写练习记录、正式变式题可判分并制成复习卡。普通完整回归也会包含这些检查，不触发真实模型验收。

已有真实产物时，可追加 `--eval-run=本轮目录名`，将其中成功生成的原文装入一次性验收空间并截图。这个预览只检查渲染，不重新调用真实模型；结束会清理验收空间。

新生成时还会拒绝未支持字段，防止模型把正文放入 `formula.content` 等渲染器不会读取的位置；修复应将解释移到合法文字块。历史文档读取保持原契约。

## 超时与重试（2026-10-28 修正）

生成、改造与追问使用同一传输策略。以下数值单位为秒，是等待上限，不是预计完成时间：

| effort | 首段有效正文 | 正文开始后空闲 | 单次流式总时限 | 单次非流式响应 | 复核整阶段 |
|---|---:|---:|---:|---:|---:|
| low | 90 | 60 | 180 | 120 | 90 |
| high | 180 | 90 | 360 | 240 | 90（固定 low） |
| max | 300 | 120 | 600 | 360 | 90（固定 low） |

正文、改造、修复与追问预算依据显式 effort，其次采用环境回退；旧客户端未传档位或环境使用 medium 时，等待预算按 high。保存前内容复核固定主模型 low，整阶段采用 low 的 90 秒预算，与正文档位分开。传输常量仍按 `src/lib/llm/client.ts` 中的 `requestTimeouts` 分档；复核调用明确传 low。

首段正文预算从发起请求开始，覆盖尚未返回响应头的时间；首字前的静默无法证明断网，不再另用较短网络空闲计时抢先中止。思考片段、心跳和空白都不能延长首字预算，正文开始后只有有效正文能续期空闲计时。流式总时限始终保留，防止持续循环输出。

正文等待、正文停顿、流式总时限和非流式响应超时直接结束该次请求，不自动重跑长思考。临时 HTTP 错误、连接明确中断或空响应仍保留最多两次传输重试；用户取消不重试。复核预算覆盖自己的请求、重试与退避，不按重试重新续期。

各上限相互重叠，不能相加作为预期耗时；流式/非流式为每次上游请求的预算，复核是整个阶段预算，并不代表整条生成—修复流程的统一总时限。一次文档修复机会保持不变；正文档位保持用户所选，复核明确固定 low。

服务端在每个模型调用阶段结束时输出 `[llm/timing]`：`phase`（generate/refine/ask/repair/review）、`effort`、`durationMs`、`attempts`、`outcome`。等待超时可区分首字、正文空闲、流式总时限和非流式响应；外层预算为 deadline，主动取消为 cancelled。日志不含请求地址、模型名、密钥、输入、生成正文或思考内容。

无付费定向回归仍使用 `python test/run-learning-loop.py --transport-only` 和 `--review-only`。传输测试缩放实际预算，验证超过旧上限的 high 思考及延迟响应头可完成、low 到限只请求一次；同时覆盖真实断线重试、正文停顿、循环输出、取消和日志元数据。桌面验证等待文案与实际策略一致。普通缺陷修正沿用本指南，不另建 spec。

本次生产构建、修改文件定向 ESLint、传输接口/桌面回归及内容复核回归通过；补充的非流式测试验证 high 修复响应跨过旧预算仍能完成，而 low 到限不自动重跑。实际查看了 `data/generation-waiting-desktop.png`。这些检查使用本地模型替身与缩放计时，未额外调用真实模型，不能据此推导线上成功率或提速幅度。

## 内容核对依据

以下页面于 2026-10-27 直接读取，仅用作核对依据，未向模型注入参考页面的全文：

- [OpenStax：Mathematics of Waves](https://openstax.org/books/university-physics-volume-1/pages/16-2-mathematics-of-waves)：频率、周期、振幅和角频率的含义。
- [Python 教程：Defining Functions](https://docs.python.org/3/tutorial/controlflow.html#defining-functions)：函数调用与递归语境；阶乘算例另外逐步复算。
- [Princeton Algorithms：Quicksort](https://algs4.cs.princeton.edu/23quicksort/)：分区过程、随机化与最坏情况；具体序列单独跟踪核对。
- [British Council：Count nouns](https://learnenglish.britishcouncil.org/grammar/english-grammar-reference/count-nouns)：辅音/元音加 y 的复数变化与不规则复数。
- [Attention Is All You Need](https://arxiv.org/html/1706.03762)：编码器/解码器、交叉注意力来源、掩码、残差和归一化。
- [Deep Residual Learning for Image Recognition](https://arxiv.org/html/1512.03385v1)：残差相加、恒等跳连及维度不匹配时的投影。
