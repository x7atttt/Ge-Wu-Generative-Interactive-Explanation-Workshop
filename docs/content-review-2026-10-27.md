# 保存前内容复核：实现与真实验收

> 本文记录当轮实现和实测。2026-10-28 已按 effort 调整复核等待预算并修正超时重试，当前策略见[验收指南](teaching-quality-acceptance.md#超时与重试2026-10-28-修正)，下文保留当时数值。

本轮为新生成、补练与改造增加保存前内容复核。结构合法之后，模型在独立请求中核对整篇和每个练习块的条件、答案与解析；发现问题后沿用一次自动修复，再重新检查。历史阅读和追问不触发这一步。

## 实际行为与成本

- 正常生成增加一次模型调用，复核使用主模型配置和本轮选定的 effort。改造本身仍沿用原有快速模型配置。
- 结构错误与内容错误共享一次修复预算。内容修复后，各类练习数量不得减少，避免通过删除错题绕过检查。
- 复核必须返回整篇及所有自测、填空、配对、分类块的结论；缺项、重复、非法字段或格式错误都视为未完成。模型明确无法确认关键条件时也需修复。
- 复核有独立的 90 秒总预算，涵盖网络重试。超时或服务不可用时明确失败，不保存该次讲解；这会降低错误内容直接入库的机会，也增加等待与失败成本。
- 桌面显示“正在核对题目与解析”，保留取消操作。后台复核/修复重试不会清空已生成的正文预览。预览不是已通过检查的成品，最终保存以完成事件为准。

## 程序复算的边界

标准阶乘使用整数运算，参考范围为 0 到 100。完整常数公式等式可比较；明确标为错误示例或判断任务的公式交给上下文复核。程序只在填空答案代入后的完整代码匹配受限标准递归实现、且整篇只有一个该函数定义时，检查“当 factorial(n) 返回某值给调用方时”的明确前提。自定义同名函数、多实现比较、其他语言或其他措辞均不据此自动判错。

对包含相应约定的分区讲解，程序另外给出字面数组作为初始输入、按末尾基准、`<=` 比较、从左向右扫描完成单轮分区的结果与交换下标。最多提供有限组短数组，仅作为复核与修复参考；不推断任意代码，也不把参考自动套给其他分区变体。

这不是通用算法验证器。模型仍可能漏检、误判或提出错误修复建议，因此修复提示要求重新求解，不能直接复制复核意见。

## 真实调用记录

输入复用上一轮本机保存的完整原文，没有重新抽样替换错题。对照采用提示词中的波形与语言示例。各轮分开记录，effort 均为 low；没有读写个人学习库，也没有联网检索。

| 轮次与案例 | 检查结果 | 耗时 | 实际模型请求 |
|---|---|---:|---:|
| 首轮：原始递归错题 | 模型误放行，漏掉 `factorial(3)` 返回 2 的错误前提 | 15.02 秒 | 1 |
| 首轮：原始排序错题 | 指出答案与解析矛盾 | 11.88 秒 | 1 |
| 首轮：波形、语言对照 | 均未报告问题 | 13.15 / 10.73 秒 | 各 1 |
| 补程序检查：原始递归 | 直接指出应返回 6 | 约 1 毫秒 | 0 |
| 补程序检查：原始排序 | 指出问题，但其建议的另一个分区结果也算错 | 32.95 秒 | 1 |
| 同轮：波形对照 | 复核超时，没有放行 | 90.00 秒 | 1 |
| 同轮：语言对照 | 未报告问题 | 14.51 秒 | 1 |
| 递归真实修复回放 | 修复后通过结构和内容复核 | 26.87 秒 | 2 |
| 补分区参考后：原始排序 | 给出正确的关键分区数组，继续指出题目矛盾 | 26.64 秒 | 1 |

“未报告问题”不是事实准确性认证。尤其首轮递归证明：仅增加一个模型审查角色，仍可能照单全收错误前提。排序复核的建议也不是可靠的计算依据，必须独立核对。

在补分区参考前，模型曾把 `[3a,1,3b,2]` 的最终结果错说成 `[2,3a,3b,1]`，并误称两个 3 未颠倒。程序复算为 `[1,2,3b,3a]`，交换下标依次为 `(0,1)`、`(1,3)`；补参考后的真实复核采用了这个数组，并保留相等元素顺序颠倒的结论。其理由里仍有个别位置描述不准确，没有据此给复核结论标“完全正确”。

递归回放仅把第一段模型输出替换为上一轮原始文档，后续修复与复核均调用真实服务；它不能代表从零生成的成功率。人工查看产物确认：题面从“返回 2”改为“返回 6”，正确选项改为 `4×6`，解析改为 `4×6=24`，原有练习保留。

本机原始记录位于 `data/content-review-eval/` 的 `first-20261027`、`final-20261027`、`repair-20261027`、`grounded-20261027` 四个目录。它们保存各轮清单、原文和模型正文结论，不保存地址、密钥或思考正文。目录名只是运行标签；后续增加分区参考的版本以最后补测为准。生成时的提交号对应当时 HEAD，变更尚在工作区，不能把它当作已提交的实现版本。

## 自行验证

停止开发服务并完成生产构建后，无付费回归：

```shell
pnpm build
python test/run-learning-loop.py --review-only
```

真实复核必须显式开启，并需要本机上一轮原文：

```shell
node test/run-content-review-eval.mjs --help
node test/run-content-review-eval.mjs --live --run=my-review --effort=low
node test/run-content-review-eval.mjs --live --run=my-repair --effort=low --repair-recursion
```

可用 `--case=sorting` 缩小复核范围。脚本使用与讲解验收相同的本机源码加载环境，产物存入新目录；不覆盖已有轮次。真实请求数、服务失败和模型误判必须保留，不把多轮择优拼接成成功率。

工程验证包括：生产构建、定向 ESLint、完整学习闭环回归；补分区参考后另跑内容复核定向回归。新测试覆盖全部练习类型、一次修复预算、错误/缺失复核、无法确认、服务失败、取消上游、重试总预算、预览保留和禁止删题。桌面阶段截图为本机 `data/content-review-desktop.png`，已实际查看。未增加窄屏适配。
