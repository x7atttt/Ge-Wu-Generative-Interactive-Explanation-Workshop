# Prompt 链快照 · AI 协同开发实录

> 本文档记录「格物」运行时提示词链与开发期 AI 协同链的**真实快照**（摘自 `src/lib/llm/prompts.ts` 与开发对话），作为 Vibe Coding 过程材料。共 4 条链，前两条是运行时（用户使用产品时触发的链），后两条是开发时（AI 与开发者协作构建产品的链）。

---

## 链 1 · 讲解生成管线（运行时，最核心）

**触发**：用户输入概念 / 点击概念地图 / 拍题，流式产出交互讲解 JSON。

```
[阶段1 系统提示词 · 节选自 generateSystemPrompt]
你是「格物」的讲解设计师。用户给你一个概念，你设计一篇可交互的讲解，
只输出一个 JSON 文档（不要 markdown 代码块）。
十种块（按讲解顺序排列）：
1. {"type":"heading",...}  2. {"type":"text",...}  3. {"type":"formula",...}
4. {"type":"slider","var":"变量名","label":"显示名","min":数,"max":数,...}
5. {"type":"wavePlot","terms":[{"fn":"sin|cos","amp":槽,...}]}
6. {"type":"chart","chartType":"bar|line|area|pie|hbar|radar",...}
   只用于离散数据；**禁止**手写 sin/cos 函数值表——函数曲线一律用 wavePlot
交互选型（按主题选择，交互必须服务于理解，不是每篇都需要滑块）：
- 量化规律：formula + slider(1~3 个) + wavePlot 或 chart
- 图表不是必需品：只有当离散数据对比真正比文字直观时才生成……
- **每个滑块必须至少被一个 {"$var":...} 引用**——没有被引用的滑块拖动毫无效果

[阶段2 用户消息 · 服务端组装]
概念：正弦波的频率
源文档资料（用户导入的文档，讲解的事实依据）：《操作系统复习讲义》……

[阶段3 输出 → zod 校验]
结构约束在 schema 层硬校验（滑块被引用/quiz 答案下标/数据长度一致……）

[阶段4 自修复（校验失败时追加一轮）]
System: 你是修复器……
User: 上面的输出存在问题：blocks[3]: 滑块 f 未被任何 wavePlot/chart 的
      {"$var":...} 引用，拖动将无效果……
      请输出修复后的完整 JSON 文档。
```

**设计要点**：①提示词声明 DSL 契约、schema 层机器校验兜底——"信任但验证"；②自修复只重试一次，带具体错误路径；③"禁止手写三角函数值表"等规则全部来自实测 badcase 的沉淀。

## 链 2 · 拍题生成与带图追问（运行时，多模态）

**触发**：用户在生成框 📷 附题目照片（概念留空），或在讲解内粘贴截图提问。

```
[生成 · 用户消息的 parts 组装]
{type:"text", text:"概念：图片讲解\n（用户附带了 1 张图片——拍摄/截图的学习材料
 （题目、教材、笔记等），讲解围绕图片内容展开，概念名按图片主题确定）"}
{type:"image_url", image_url:{url:"data:image/jpeg;base64,…"}}   ← 前端压缩至长边1280

[追问 · 问题在最后一条 user 消息]
{type:"text", text:"这题为什么选 B？\n（附 1 张图片，问题围绕图片内容）"}
{type:"image_url", …}
```

**实测样例**：输入一张红白蓝三色竖条图、概念留空 → 生成讲解《从一面红白蓝旗帜说起：法国三色旗》（模型识别出图片语义并以此定题）。

## 链 3 · 逐章学习路线（运行时，LLM+规则混合）

**触发**：概念地图点"生成学习路线"。

```
[系统提示词 · 节选]
你是「格物」的学习规划师。……请把全部概念编排成 3~8 站的学习路线：按学习依赖与
认知难度从易到难……硬性规则：只能使用清单中出现的概念名，原样复制不得改写；
每个概念只能出现在一站；必须覆盖清单中的全部概念。
只输出一个 JSON 对象：{"stages":[{"title":"站名","goal":"目标一句话","concepts":[…]}]}

[用户消息]
空间：期末·操作系统（考纲+课件+真题）
考试日期：2026-11-18
资料与概念清单：
《操作系统复习讲义》：进程与线程的区别、进程三态与PCB、……

[服务端后处理（确定性，不信任 LLM 的"必须"）]
白名单过滤改写名 → 跨站去重 → 剔空站 → 覆盖兜底：
未编排概念自动补入「查漏补缺」站
```

**实测发现**：模型两次都漏排同一个概念（分页与虚拟内存）——"必须覆盖"类提示词不可靠，确定性兜底才可靠。

## 链 4 · FSRS 算法迁移（开发时，AI 协同的典型样本）

**任务**：把复习调度从 SM-2 升级为 FSRS-6，正确性要求"逐位对齐开源参考实现"。

```
[轮1 开发者 → AI] 接入 FSRS 调度
[AI] 先查证再动手：直读 ts-fsrs 源码（constant.ts 默认参数 / algorithm.ts 公式），
     自研 lib/fsrs.ts 纯函数，并写 scripts/fsrs-verify.mjs 对照脚本逐序列比对

[轮2 对照脚本首跑]
FAIL fuzzy+again[0] interval: mine=2 ref=3
FAIL 同日连评[1] interval: mine=8 ref=10
→ AI 定位根因①：参考实现有四档间隔单调链（good≥hard+1…），单档计算差1-2天
→ AI 定位根因②：均值回归使用未 clamp 的 D₀(Easy)（可为负），每步偏差 0.001×5.77

[轮3 修复后]
6 条评分序列 27 次比对 D/S/间隔全部一致（<1e-6）——两处公式级偏差
不与参考实现并排对照根本发现不了，已沉淀进 spec
```

**结论**：AI 生成的算法代码"看起来对"和"逐位对"之间隔着一套可执行的验证脚本——这是本项目 AI 协同的代表性方法论（smoke 脚本至今常驻 `scripts/`）。
