# 内容完整性与确认流程 · 开发协作记录

> 本文为事实摘要，并非原始对话导出。

## 用户反馈

用户提供浏览器标记与截图，要求修复：取消删除后继续询问、原生确认窗简陋、Markdown 符号裸露、代码填空平铺、参数仅影响单柱、学习状态颜色相近、自测卡缺少选项及题干残缺。

## 定位与选择

- 删除逻辑把拒绝深度删除当成进入普通删除的条件；改成同一弹层内明确选择，取消终止当前动作。
- TextBlock 原先直接渲染字符串；练习与卡片也存在纯文本展示。沿用已有 Markdown 渲染器，代码填空保留真实空白和历史换行标签。
- 制卡只复制选择题 question，丢弃 options；改成完整独立题面。旧卡只按题面和答案精确匹配补全，避免覆盖用户编辑。
- 截图递归图仅第一个数据槽绑定参数，其余都是常量；修正为当前 n 的两组同步比较，公开实际绑定范围。
- 学习状态语义不同，但图例错误复用了颜色；未作答状态改称“待练习”，与“待巩固”统一使用不同颜色和说明。
- 存储 schema 继续加载旧数据，生成阶段追加质量门，复用一次自动修复。残缺旧卡不能通过自评改变记忆排期。

## 验证引导出的调整

- 保留完整冒号选择题的合法性，残缺逗号题干独立标记，避免把正常引出选项的题干误判。
- 增加 Python 复合语句缩进检查，同时允许正常单行表达式填空。
- 浏览器测试最初的部分文本定位同时匹配选项和答案，改为精确定位；随机题序切换改为等待答题响应和题号更新，避免测试抢在界面更新之前推进。
- 已完成报告保留快照；进行中自测补全兼容。删除后的跳过与残缺题跳过均不计分。
- 本地目标讲解修正前备份，修正截断正文、代码、图表与歧义题干，只更新精确对应自动卡的内容字段。
