# 迭代19：跨概念综合测验卷——空间全量卡随机抽卷、按概念出分

> 状态：done
> 创建：2026-10-16
> 关联：2026-10-12-iteration18-srs-cards-countdown.md（卡池与调度基础设施）

## 背景

迭代18 之后，复习（SM-2 到期队列）解决"每天该复习什么"，但备考用户在考前还需要回答"我现在整体掌握得怎么样"。当前没有一种方式把空间内**所有概念**的卡混在一起模拟一次考试：复习队列只含到期卡，讲解内练习只覆盖单个概念。根因：缺少一个跨概念、全量抽样的测验形态。

## ★ User Stories

- 作为备考用户，我想用空间内**全部**复习卡（不限到期）随机抽一份模拟卷，以便考前检验整体掌握度。
- 作为备考用户，我想在卷末看到总分与**按概念的分项成绩**，以便定位薄弱概念。
- 作为备考用户，我想测验中答错的卡自动进入今日复习队列，以便考后立刻补漏。
- 作为系统，我想测验评分沿用 SM-2 调度写回，以便复习与测验共享同一套记忆状态（不另起一套分数）。

## 目标 / 非目标

**目标**：测验抽样 API、测验会话 UI（复用翻面/三档/键盘/音效交互）、卷末分概念报告、概念地图入口。

**非目标**：不做限时、不做题型配置、不做判分自动化（卡是开卷自评制，与复习一致）；不生成新卡。

## ★ 方案

| 决策点 | 选择 | 理由 |
|---|---|---|
| 抽样范围 | 空间内全部卡（不看 due） | 模拟考检验的是整体记忆，不是今日任务 |
| 抽样方式 | SQL `ORDER BY RANDOM() LIMIT n`，默认 20 | 卡池量级（几十~几百）下随机抽样足够，无需分层 |
| 评分写回 | 复用 `POST /api/cards/[id]/review`（SM-2 三档） | 测验即复习：again → due=今日（考后补漏），easy/fuzzy 正常推后；单一事实来源 |
| 计分口径 | easy=1 分、fuzzy=0.5 分、again=0 分，卷面百分制 | 自评三档的自然映射，模糊给半分符合"想起来了但费劲" |
| 分项报告 | 客户端按 `originConcept` 聚合本次评分 | 数据全在会话内，无需新后端聚合端点 |
| 队列行为 | 测验中**不**把 again 追加到卷尾（与复习不同） | 考卷每题只出现一次；补漏交给考后的今日复习队列 |
| 组件形态 | 新建 `ExamPanel`，视觉与交互模式沿用 `ReviewPanel` | 差异（队列源/追尾/报告屏）是流程性的，合并成 mode 分支会让两处都难读 |

### 外部依赖

无新外部依赖。复用迭代18 的 cards 表与 `/api/cards/[id]/review` 契约。

## 边界 case

- (story 1) 空间无卡 → 入口按钮不出现（与复习入口同条件 `cards.total > 0`），不存在空卷请求。
- (story 1) 卡池小于抽样数 → 返回全量（`LIMIT` 自然截断，`count` 是上限）。
- (story 1) `count` 缺省 → 20；非法（非正整数 / >100）→ 400。
- (story 4) 评分请求时卡已被并发删除 → 沿用 review 端点 404，前端展示错误、不推进本题（可重试或退出）。
- 中途退出 → 已评部分已写回调度，卷面报告丢弃（退出即弃卷）。
