# 迭代22：逐章学习路线——空间概念按依赖与难度编排为学习路径

> 状态：done
> 创建：2026-10-17
> 关联：2026-10-12-iteration16-knowledge-spaces.md（概念地图与概念来源）；2026-10-16-iteration19/20（同一空间的复习/测验生态）

## 背景

概念地图把空间的全部概念平铺成状态色块，回答"有哪些、学得怎样"，但不回答"**先学哪个**"。一门课的讲义概念间有依赖顺序（先进程再调度、先互斥再死锁），用户面对十几个"未学"色块时缺少一条可执行的路径。根因：概念集合有序（资料顺序），学习顺序（依赖/难度）无人编排。

## ★ User Stories

- 作为备考用户，我想把空间内全部概念一键编排成 3-8 站的学习路线，以便按依赖顺序逐站攻克。
- 作为备考用户，我想每一站看到包含的概念及其当前状态（未学/薄弱/已练成），以便点击直接开始（生成讲解/补练/打开讲解，与地图同款分派）。
- 作为备考用户，我想看到每站完成度与"当前站"标记，以便知道下一步该做什么。
- 作为备考用户，我想重新生成路线（资料或提炼变化后），以便路线跟当前概念集保持一致。

## 目标 / 非目标

**目标**：spaces 存 roadmap（JSON）、LLM 生成 API（概念名白名单约束 + 后过滤）、概念地图下方路线面板（站点/完成度/当前站/点击分派/重新生成）。

**非目标**：不做逐站打卡/解锁机制（完成度由概念状态自然推出）、不做人工拖拽调整顺序、不做按考试日期倒排的每日计划（后续可加）、不生成新讲解内容。

## ★ 方案

| 决策点 | 选择 | 理由 |
|---|---|---|
| 编排者 | LLM（fast 模型，jsonMode） | 依赖/难度排序是语义判断；输入只有概念名+资料标题，成本极低 |
| 概念白名单 | 提示词强约束"只能使用提供的概念名，原样复制" + 服务端后过滤（未知/重复概念剔除，剔除后空站丢弃） | LLM 改写概念名会断开与地图的对齐；提示词防大半、过滤兜底 |
| 存储 | spaces.roadmap（JSON 字符串）+ roadmap_at（生成时间），幂等 ALTER | 路线是空间级派生数据，重生成覆盖；不建独立表 |
| 读取路径 | 并入 `GET /api/spaces/[id]/map`（SpaceMap 加 roadmap 字段） | 面板一次拉取；不另开 GET |
| 生成入口 | `POST /api/spaces/[id]/roadmap` | 与既有 action 型 POST（from-doc/concepts）同款 |
| 站点进度 | 站内概念 status===practiced 计为完成；全部完成前的第一站标"当前站" | 不引入新的打卡状态，概念状态是唯一事实源 |
| 概念缺失容错 | 路线里的概念在地图找不到（资料被移走等）→ 按未学样式渲染，点击走 onPick(text, []) | 路线是快照，地图是实时；容错而非强制失效 |
| 生成条件 | 空间概念总数 ≥2 才出入口/接单 | 1 个概念无"路线"可言 |

### 外部依赖

复用既有 LLM 基础设施（lib/llm/client fast 模型 + jsonMode），模式与 `api/sources/[id]/concepts` 完全同款（extractJson 栅栏剥离 + zod 校验）。无新外部依赖。

## 边界 case

- (story 1) 概念 <2 → POST 400（"先在各资料提炼讲解点"）；UI 不显示入口。
- (story 1) LLM 输出含未知概念 → 后过滤剔除；整站剔空 → 丢站；全部丢空 → 500（带"请重试"文案）。
- (story 1) 同一概念被排进多站 → 保留首站，后续剔除（进度不重复计）。
- (story 4) 重新生成直接覆盖（无确认）——生成便宜且可反复；路线非学习资产。
- (story 2) 点击"未学"概念而其资料已不在空间 → onPick 收到空 sourceIds，生成不带附加资料（宽容路径）。
- 考试日期已过/未设 → 提示词不注入日期信息，排序不受影响。

## ★ 实测结果

### 改动清单

- `lib/db/index.ts`：spaces 加 roadmap/roadmap_at 列（幂等 ALTER）
- `lib/db/spaces.ts`：RoadmapStage 类型、SpaceRow 解析（坏 JSON 容错为 null）、setRoadmap、SpaceMap 透出 roadmap/roadmapAt
- `app/api/spaces/[id]/roadmap/route.ts`（新路由）：fast 模型 jsonMode 生成 + zod 校验 + 白名单后过滤 + 跨站去重 + 剔空站 + **覆盖兜底**
- `lib/api/spaces.ts`：SpaceInfo/SpaceMap 字段、generateRoadmap
- `components/SpaceMapPanel.tsx`：地图下方路线面板（站点/目标/概念色块复用地图分派/完成度/当前站朱砂标记/生成与重新生成）

### 验证 case 结果

| 测试 | 结果 |
|---|---|
| 空间4（无概念）POST roadmap | 400「概念不足 2 个——先提炼讲解点」 |
| 上传《操作系统复习讲义》txt → 提炼 8 概念 | OK（source 9） |
| 生成路线（首跑，无兜底版） | 5 站 7 概念：白名单外 0、重复 0，**漏 1 概念**（分页与虚拟内存） |
| 加覆盖兜底后重新生成 | 6 站 8/8 全覆盖，「查漏补缺」站确定性补入被漏概念 |
| GET map 含 roadmap | 站数 6、roadmapAt 一致 |
| tsc / 首页渲染 | 通过 / 200 |

### 实施中发现的问题

- **提示词"必须覆盖全部概念"不可靠**：两次生成模型均漏同一个概念（分页与虚拟内存，讲义第五章）——覆盖率靠提示词只有 ~；最终方案是确定性兜底：过滤后将白名单内未编排概念自动补入「查漏补缺」站，保证路线 ⊇ 概念集的硬不变量。
- 测试数据已保留在「测试空间」（讲义 source 9 + 8 概念 + 6 站路线）供用户直接做 UI 验收。
