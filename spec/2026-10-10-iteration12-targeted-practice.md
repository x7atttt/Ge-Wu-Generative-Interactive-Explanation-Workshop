# 迭代 12：针对性补练（学习闭环收口）

> 状态：done
> 创建：2026-10-10
> 关联：spec/2026-10-10-iteration10-learning-stats.md（弱项清单即本迭代入口）

## 背景

迭代 10 上线了练习埋点与统计仪表盘，弱项清单只到"看见"为止。路线图要求把学习闭环走完：**统计 → 再生成**——弱项概念一键生成针对性练习讲解。这是"从生成工具到学习闭环系统"叙事的收口点，也是创新性论证的核心一环（AI 依据学习者数据自适应出题）。

## User Stories

- 作为终端用户，我想在统计面板的弱项概念上一键「补练」，以便针对薄弱题型获得新练习。
- 作为系统，补练的统计输入必须由服务端自己从 DB 聚合（不信任客户端上报的数字），以便数据可信。
- 作为终端用户，没有练习记录或概念已删除时，我要得到明确错误而不是一次错误的生成。

## 方案

| 决策点 | 选择 | 理由 |
|---|---|---|
| 入口 | 统计面板弱项行的「补练」按钮 → 复用生成主流程 | 闭环动线最短；生成区的构建面板/取消/落库全部免费复用 |
| 概念来源 | 服务端取源文档标题为概念 | 统计归属该文档，概念必须一致 |
| 统计注入 | 服务端聚合为若干行（总体 + 按题型正确次数），作为「练习统计」段进用户消息 | 与网络检索参考资料同构（用户消息附增强信息段），管线复用 |
| 提示词 | generateSystemPrompt 的 practice 模式：换导语、补练选型（练习块 ≥5、薄弱题型多出）、去示例（prompt 省 ~40%） | 补练不需要 few-shot（结构约束在块清单里已完整）；短 prompt 降延迟 |
| 联网检索 | 补练模式跳过 | 统计已占增强信息位；概念知识模型已具备（来自同一文档的生成历史） |
| 可视化 | 允许"概念必需"时保留图（如频率概念配波形图） | 提示词明示"除非概念必需"；教学需要优先于形式纯粹 |
| 落库 | 新根文档（parent_id null） | 补练是独立练习文档，不属于原讲解的 refine 版本链 |

## 边界 case

- (story 3) practiceDocId 无练习记录 → 400「该概念还没有练习记录，无法补练」
- (story 3) practiceDocId 不存在 → 400「补练的概念不存在」
- (story 2) 客户端只传 practiceDocId，数字全部服务端聚合
- 补练文档自身的练习照常埋点（AttemptProvider 随新 docId 提供）——补练效果可被统计观察

### 实施中发现的问题

- E2E 首版断言"补练零滑块"过严——提示词契约是"除非概念必需"，模型为频率概念保留波形图是正确判断；断言修正为"练习块为主体"，并在 spec 记录该设计决策。
- `pnpm build` 会清空 `.next` 导致共用目录的 dev 服务器崩溃（连续两次复现）——build 与 dev server 不能同时在同一项目目录运行；后续验证顺序改为先 build 后起 server，或在用户服务器运行期间避免 build。
- getDocAttemptStats 首版漏了 block_type→blockType 映射（与迭代 10 listDocs 同款蛇形/驼峰坑），build 拦截。
