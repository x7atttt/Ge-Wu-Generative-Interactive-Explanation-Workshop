# MVP 范围定义：概念 → 交互讲解 → 一轮改造的完整闭环

> 状态：implementing（2026-09-24 与项目所有者对齐后开工）
> 创建：2026-09-24
> 关联：`2026-09-24-dsl-schema-v0.md`（DSL 契约细节见该文档）

## 背景

现有 AI 助手解释抽象概念时只给"文字 + 静态图"，学习者无法动手调节参数获得直觉。本项目让用户输入一个概念（如"正弦波的频率"），AI 现场生成一个带滑块的交互式可视化讲解，并支持生成后用一句话继续改造。MVP 的目标是跑通这条价值链的最小闭环，验证"生成 → 渲染 → 改造"链路的可行性与体验。

## User Stories

- 作为学生，我想输入一个概念并获得一篇交互式讲解，以便通过拖动参数建立直觉。
- 作为学生，我想拖动滑块时**立即**看到波形变化，以便感知参数与结果的因果关系。
- 作为学生，我想用一句话改造已生成的讲解（如"把振幅固定为 2"），以便把讲解调整到我关心的情形。
- 作为系统，我要校验 LLM 输出的文档结构合法（含变量引用一致性），以便渲染层永不收到坏数据。

## 目标 / 非目标

**目标**

1. `POST /api/generate`：概念字符串 → 合法 ExplainDoc（DSL v0）
2. `POST /api/refine`：ExplainDoc + 改造指令 → 新 ExplainDoc
3. 渲染层支持 4 种块：text / formula / slider / wavePlot，wavePlot 的数值槽可绑定滑块变量
4. LLM 接入采用 **OpenAI 兼容协议 + 可配置 base_url / model / api key**（环境变量），不绑定任何厂商
5. 校验失败时自动携带错误信息让 LLM 自修复一次（重试上限 1）

**非目标**（后续迭代）

- 音效两档（已定案、暂缓）、高级模式 Sandpack 沙箱、视频导出、TTS
- 流式输出（SSE）与思考过程可视化
- 讲解历史持久化、账号系统、分享链接
- 多轮复杂对话上下文管理（refine 每次只基于当前文档）

## 方案

| 决策点 | 选择 | 理由 |
|---|---|---|
| LLM 协议 | OpenAI 兼容 `POST {base_url}/chat/completions`，原生 `fetch` 不用 SDK | 零 SDK 依赖、全厂商通用（GLM/DeepSeek/OpenAI 等均兼容），演示时可随时换模型 |
| LLM 配置 | `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 环境变量 | 密钥不入库；`base_url` 去尾斜杠后拼接路径 |
| 结构化输出 | `response_format: {type:"json_object"}` + zod 校验 + 1 次自修复重试 | json_object 比 json_schema 兼容面广；重试显著提升健壮性且成本可控 |
| 波形表达 | terms 求和模型（`y = Σ amp·fn(2π·freq·x + phase)`），数值槽为常量或 `{"$var": 名}` | 无表达式解析 = 无注入面、无解析器 bug；天然支持滑块绑定与傅里叶叠加场景 |
| 组件扩展 | 块类型判别联合 + 渲染注册表 | 新组件 = schema 加分支 + 注册表加一项，不动核心链路（可扩展性要求） |
| 前端状态 | 变量值放 React Context，滑块直写、图直读 | 直接操作 1:1 跟手（动效原则）；无全局状态库必要 |

### 外部依赖

- OpenAI Chat Completions 协议（各厂商文档为准；示例 base_url：GLM `https://open.bigmodel.cn/api/paas/v4`、DeepSeek `https://api.deepseek.com`，模型名以账号可用列表为准）
- zod 4.6.5（校验）、motion 13.4.1（过渡）、mafs 0.21.0（波形图）、katex 0.18.9（公式）

## 边界 case

- (story 4) LLM 返回非 JSON / 缺字段 / 变量引用未定义 → zod 报具体 issue → 携带错误自修复重试 1 次 → 仍失败返回 500 + 友好错误文案
- (story 4) LLM 返回被 markdown 代码栅栏包裹 → 剥离 ```json 围栏后再解析
- (story 4) 环境变量缺失 → 生成请求返回指引性错误（提示配置 .env.local），而非堆栈
- (story 1) 空输入 / 概念超 200 字 / 指令超 300 字 → 400 + 明确提示
- (story 2) 滑块 initial 落在 [min,max] 外 → schema 层不硬拒（浏览器 range 会夹紧），渲染层取夹紧值显示
- (story 3) refine 返回的文档丢块/换题 → schema 校验兜底；不做语义 diff（超 MVP）

## 验证方案

- [ ] build：`pnpm build` 通过

- [ ] 拖动频率滑块，波形无动画延迟地即时变化
- [ ] 输入「傅里叶级数」→ 生成多 terms 叠加波形
- [ ] 输入改造指令「把振幅固定为 2」→ 文档更新且公式/滑块同步

- [ ] 输入空概念 → 400 提示

## 不在本次范围（Out of Scope）
